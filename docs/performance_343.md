# 3.4.3 性能开销测试方法

**状态：用户于 2026-10-18 要求结束测试。已停止当前轮及后续队列；全量微基准未开展，受控剖析对照未完成。下表记录测试设计，不表示所有项目已完成。**

本轮监控、无故障和微基准前缀 `s343-r1-`，受控剖析前缀 `s343-r2-`，使用最新交接修订的源码。原始结果保留在各 run 目录，单轮以 manifest 和双节点下载完整为完成条件。源码及运行库校验另见 `results/s343-r1-provenance.json`。测试只使用自己的训练进程，不调整共享 GPU 时钟、不制造背景流量、不注入停机。

## 与论文对齐的测试项

| 项目 | 本轮配置 | 解释边界 |
|---|---|---|
| 数值前置检查 | 两节点 16 rank，EP8，3 步 verify | 所有 rank 首步数值验证通过才运行后续矩阵 |
| 监控端到端开销 | 每轮 250 步，无 padding；关闭/开启/开启/关闭（ABBA） | 论文只要求开关对照，ABBA 是控制顺序漂移的补充；主要统计第 6 步起的完整周期 |
| AllReduce 微基准 | 4/8/16/32/64/128 MiB；每档预热 500 次，正式 10,000 次，每批 100 次；关闭/开启一对对照 | 论文写 MB，未明确十进制/二进制；本实现明确 2²⁰ 字节。每 rank 每档 100 个批均值 |
| 无故障观察 | 独立 1,800 步，无 padding、无故障、自动检测开启 | 只能报告实际观察时间与触发次数，不能代替连续数周误触率评估 |
| 剖析开销 | 每轮 1,800 步；关闭/强制剖析/强制剖析/关闭；step200 后触发 | 延长训练以覆盖至少 20 秒剖析；必须核对本地完成上报及训练样本覆盖，强制触发不计误触 |

## 计时口径

训练的主要计时用 rank0 相邻 `step_start_time` 之差，包含迭代记录写入、Redis 上报、下一迭代准备和同步等跨步开销。原 `time_ms` 在日志及上报之前结束，只作辅助训练区段指标。去掉零基步号 0–4；最后一步缺少下一步起点，不进入完整周期统计，因此 250 步每轮提供 244 个稳定周期。

时延开销为 `100 × (FLASH平均周期 / baseline平均周期 - 1)`；相对吞吐变化为 `100 × (baseline平均周期 / FLASH平均周期 - 1)`。两者不是同一百分比。辅助提供中位数及各 run 的数值，避免均值掩盖波动。受控剖析使用 `--force-profile-only`，在该轮关闭自动触发；它只隔离开销测量，不更改普通运行的检测规则。旧 `s343-r1-profile-1-flash` 曾提前自动触发，保留为误触证据并排除受控剖析对照。剖析窗口按双节点本地状态交集选取，边界剔除，按相同步号匹配无 FLASH 基线；完整剖析事务另外报告均值以观察长尾成本。

微基准默认按论文完成一组关闭/开启对照；`--collective-abba` 可增加第二组作为补充，但本轮未计划该额外重复。共享 Socket 环境单个完整微基准轮预计约半小时。

微基准在当前 CUDA 流上用起止 Event 包住连续 100 次 AllReduce，只在批边界同步，将整批耗时除以 100；同时保存主机墙钟批均值。两种口径都包含批内调度影响。监控对照启用探针、本地控制器和全局控制器，但微基准没有训练迭代输入，因此全局检测器仅空轮询；不能把它当成端到端控制器开销评估。重复次数仍是每档 10,000 个实际调用，不把 16 个 rank 或同轮 100 个批均值当成独立实验重复。

监控态本地 reader 跳过历史记录，只观察进度；结尾 snapshot 重新从序号 0 读取时的 `lost_on_snapshot` 可能只表示正常环滚动，不代表剖析采样丢失。剖析丢失应核查本地 `profile_reported.lost` 和计时错误字段。


## 结论限制

本环境为共享 H800、NCCL Socket/bond0、约 0.526M 参数的 MoE-only 合成负载；论文为 H200、Qwen 13.3B MoE、不同通信与软件环境。本轮报告本环境相对开销，不推算论文 TFLOP/s，也不把论文 0.05% 监控开销、微基准最大低于 0.8%、剖析不超过 5% 当作已实现结果。负差异保留为测量波动，不能表述为 FLASH 加速。
