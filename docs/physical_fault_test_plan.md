# 真实故障注入与定位：少量覆盖测试

**本轮未采用此物理注入方案。用户随后明确选择“继续用进程内代理，并明确不算真实限频或背景拥塞”。本轮实际矩阵为 `results/loc-r1-matrix.json`，不改变 GPU 频率、不启动背景流量。下文仅保留真实注入所需条件与方法差异。**

## 目的与当前状态

用户要求覆盖 GPU 物理限频和真实背景流量，尽量全面但不大量重复。对应论文 3.4.4 的准确率实验；3.4.3 用于参考常态开销和误触观察。排除停机、OOM 和 NCCL timeout。

此前现有留档没有真实背景流量实验；通信 stream callback 等待属于进程内代理。物理限频只有 `paper-clock600-auto` 等预检/短测，不能与代理五档混算为物理注入精度。

2026-10-18 只读检查：两节点每台 8 张 GPU 均有 vLLM worker；两端 bond0 为 2×25GbE LACP。物理限频会影响同卡 vLLM，背景流量会竞争共享链路，与此前保护共享服务的要求存在冲突。必须先明确独占/维护窗口，或用户接受有界共享影响；在资源安排明确前不改变频率、不启动流量。

## 主矩阵：7 轮，各一次

| 轮次 | 注入 | 范围 | 用途 |
|---|---|---|---|
| N | 无 | 相同负载、自动检测 | 正常负控与误触 |
| C1 | 1605 MHz，论文 1600 MHz 的邻近受支持档 | node0 一张 GPU | 轻计算退化 |
| C2 | 900 MHz | 同上 | 中计算退化 |
| C3 | 345 MHz | 同上 | 强计算退化 |
| B1 | 低目标速率 TCP 背景流量 | node0→node1、bond0 | 轻链路竞争 |
| B2 | 中目标速率 TCP 背景流量 | 同一路径 | 中链路竞争 |
| B3 | 高目标速率 TCP 背景流量 | 同一路径 | 强链路竞争 |

可选两轮用于补足覆盖而不大规模重复：第二节点 GPU 的 C2，以及短时 B2 后恢复的瞬态负控。只有前七轮证明注入和测量有效后才考虑追加。每个设置一次只能报告描述性命中情况，不能估计稳定的总体 Precision/Recall 或置信区间。

流量低/中/高按明确的**总目标 bps**配置、保存实际接收 bps；不是用 TCP stream 数冒充故障强度。目标速率在窗口获准后据链路容量、LACP 单成员容量和短校准确定。论文的 5/25/45/65/85% 是性能退化档位，不能把频率下降百分比、背景带宽百分比直接当成训练退化百分比。

## 前置校准与训练配置

先做一次短数值 smoke 和一次无注入负载校准，不并发 GPU 矩阵。当前 64 hidden、32 token 的极小负载在历史 600 MHz 下只增加约 1.68% 迭代时间，不能保证物理限频形成可检测信号。候选负载为 `--hidden-size 128 --ffn-size 2048 --num-layers 4 --seq-len 1024`，若显存有余但计算占比仍过低，最多补一次增加 token 的校准；不得靠额外 sleep 制造“物理限频”成功。

自动定位主试验不强制剖析，不加固定 padding，不把注入位置/强度传给诊断器。注入前至少留足 100 个稳定迭代，避免启动阶段混淆。注入后训练持续至少 30 秒，以覆盖 20 秒最小剖析和汇总；频率租约、流量硬超时、训练 timeout 分别约束。具体 steps 据一次无故障校准计算，不能固定很短步数导致剖析在训练退出后才完成。

若实测退化未超过 20% 门限且未触发，应如实报告未触发；不调低门限凑命中。必要的强制采样只能作为独立“条件定位诊断”，与自动端到端命中率分列。

## 定位真值与统计

计算限频的真值是被限频 GPU 对应 rank；报告唯一 rank 是否正确、错误 rank、拒判、检测/组定位/唯一定位各阶段时延。

背景流量的干预范围是节点对/链路域，不天然属于单个 rank。报告跨节点通信组与受影响节点是否命中，以及输出 rank 的证据与歧义；不能任意指定 rank0 为拥塞根因，再据此计算单 rank 准确率。只有注入真正隔离到单 rank 专用路径、且有独立证据时，才采用唯一 rank 真值。

默认 FLASH 工程扩展版为主结果；正文规则对同一份 profile 离线重放。两版分列，不额外跑一遍训练，也不混算指标。

每轮给出注入前后平均/中位迭代时间、时延增幅、吞吐下降、计划/实测强度、自动触发与完成时刻、候选组、候选/唯一 rank、计时错误与采样丢失。正常轮单列误触。

## 真实注入验收与收尾

- 限频保存原始应用时钟、请求/测得时钟、注入实际 step、恢复后的时钟。禁止把原始 1980 MHz 硬编码替换成论文 1965 MHz；复用旧脚本时需修正它启动即设 baseline 的行为。恢复失败立即停止矩阵。
- 背景流量必须与训练实际重叠，保存训练 run ID、源/目的地址、bond0 路由、每秒发送/接收速率、字节数、重传和客户端/服务端 JSON。并行流数和计划速率都不能替代实测值。
- 启动器必须先准备接收端，在训练达注入 step 后启动发送端；训练结束或取消时立即清理自己记录的进程组，保存端口/进程清理回执。异常也落盘结果，不能只保留成功轮。
- 只停止自己的 flash2-dev 和 iperf 进程，恢复限频，刷新 final-state。新 run ID，不覆盖历史结果。
