# FLASH v1.1

## 代码范围

定位核心与NCCL probe未改动，正式v1的58个核心源码/测试文件全部逐字节一致。保留原训练入口，新增 `experiments/flash-v1-20261021/dual-view-matrix/workload_dual_view.py`（433行，复用原 `train.py`）。这属于训练负载的实质性扩展：ETP=1独立于Dense TP；Attention_DP=world/(TP×PP)，Expert_DP=world/(ETP×EP×PP)，EP与DP不是额外独立相乘的维度。新增Dense TP分片MLP、token gather/SUM伴随梯度、固定全局256 token，以及全批reference输出/梯度/AdamW核验。模型仍为tiny MoE，不是Qwen模型。

新增warm forkserver启动器及固定36项执行、评分、审查工具，保留实际执行源码与冻结身份。`workload_wrong_adjoint.py`是明确标注的负控验证程序，不是正常训练入口。历史执行脚本含原实验节点、端口和目录；先阅读协议和脚本，不应直接在共享环境重放。远程凭据不包含在本版，`scripts/remote.py`依赖本地忽略的凭据文件。

## 36项结果

四种EP/TP/PP配置为8/1/1、4/2/1、4/1/2、4/2/2，ETP均为1；覆盖两节点、PP两stage目标、14/100/200ms host到达延迟及8项无故障对照。计划28个正例+8个对照；35工程完成、1失败；28项完整资格通过（21正例+7对照）。合格子集TP=19、FP=1、FN=2，精确率95.00%、召回率90.48%；固定计划保守召回19/28=67.86%。失败与资格不足均保留，不把描述性线上命中等同于严格验收准确率，不混入旧22项或3项pilot。

这是host计算到达延迟代理，未修改GPU时钟，不等价于真实硬件降频；通信模式与原负载不同。所有结果的适用范围以筛查报告及独审为准。

## 使用与离线复核

安装GPU运行环境沿用v1的requirements及probe构建说明。单节点CPU正控示例（需PyTorch/Gloo）：

```bash
python -m torch.distributed.run --standalone --nproc_per_node=2 experiments/flash-v1-20261021/dual-view-matrix/workload_dual_view.py --help
```

先用`--help`查看实际参数，分布式训练需按协议提供EP/TP/PP、输出目录与run ID，切勿用原`workload/train.py`命令冒充双视图。

取得完整本地测试包后，可校验包级哈希：

```bash
cd FLASHv1
python3 - <<'PYCODE'
import hashlib,json,pathlib
root=pathlib.Path('.')
m=json.loads((root/'COPY_MANIFEST.json').read_text())
for row in m['files']:
    p=root/row['destination']
    assert p.stat().st_size==row['bytes'], p
    assert hashlib.sha256(p.read_bytes()).hexdigest()==row['sha256'], p
print('verified',len(m['files']),'payload files')
PYCODE
```

完整包的`COPY_MANIFEST.json`是筛选后2683个payload文件的完整性清单；原`complete36-seal.json`仅作原封存来源记录，原快照的2701项并未全部包含于本筛选包。封存文件不回写。源码镜像中的`source/VERSION`保留v1，表示原依赖身份；仓库根`VERSION`为v1.1。

全raw审查还需要原采集目录的`fdmf-*.verification.json`资格标记；仓库中已补齐这些原文件。将完整包的`source/results`与`dual-view-matrix/verification`放入同名目录后，用`independent_audit.py --final --output /tmp/flash-v1.1-audit.json`复核，输出放临时目录，不覆盖封存报告。
